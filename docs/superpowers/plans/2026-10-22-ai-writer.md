# AI Writer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Vencord userplugin for Vesktop that adds an Off/AI chat-bar toggle; in AI mode, outgoing messages (and optionally edits) are rewritten through OpenRouter before sending.

**Architecture:** Pure logic (should-rewrite check, OpenRouter call, reply parsing) lives in `ai.ts` and is unit-tested with Node's built-in test runner. `index.tsx` wires it into Vencord's `onBeforeMessageSend` / `onBeforeMessageEdit` hooks and a `chatBarButton`; `SettingsModal.tsx` edits the persisted settings.

**Tech Stack:** TypeScript/TSX, Vencord plugin API, `node --test` (Node v26, native TS stripping), pnpm.

**Spec:** `docs/superpowers/specs/2026-10-22-ai-writer-design.md`

## Global Constraints

- Plugin source lives in `aiWriter/`; Vencord checkout in `Vencord/` (git-ignored); symlink `Vencord/src/userplugins/aiWriter -> ../../../aiWriter`.
- Endpoint: `POST https://openrouter.ai/api/v1/chat/completions`, header `Authorization: Bearer <key>`.
- Body: `{ model, messages: [{ role: "system", content: prompt }, { role: "user", content: text }] }`.
- Default model: `anthropic/claude-sonnet-5-5`. "Also rewrite edits" defaults to off.
- AI mode is in-memory only and starts Off every launch.
- On any failure: return `{ cancel: true }`, show a failure toast with the reason; user's text stays in the box.
- `ai.ts` must use only erasable TS syntax (no enums/namespaces) so `node --test` can run it directly, and must not import from Vencord.

## Review Focus

1. Whitespace-only message in AI mode → passes through untouched (no API call). Test in Task 1.
2. OpenRouter returns 200 with an `error` object or no `choices` → treated as failure, not sent as "undefined". Test in Task 1.
3. Model reply wrapped in whitespace/newlines → trimmed before sending. Test in Task 1.
4. Non-2xx response (e.g. 401 bad key) → error message includes the status and OpenRouter's error message. Test in Task 1.
5. Message with only an attachment (empty content) in AI mode → sent unchanged. Covered by item 1's empty-text test; verified manually in Task 3.

### Task 1: Core rewrite logic (`ai.ts`)

**Files:**
- Create: `aiWriter/ai.ts`
- Test: `aiWriter/ai.test.ts`
- Create: `.gitignore` (contents: `Vencord/`, `node_modules/`)

**Interfaces:**
- Produces:
  - `shouldRewrite(text: string): boolean` — false for empty/whitespace-only or text starting with `/`.
  - `type RewriteConfig = { apiKey: string; model: string; prompt: string; }`
  - `rewrite(text: string, cfg: RewriteConfig, fetchFn?: typeof fetch): Promise<string>` — returns trimmed reply; throws `Error` with a human-readable message on: empty `apiKey` ("No OpenRouter API key set"), non-2xx (`"OpenRouter <status>: <error.message or statusText>"`), missing/empty `choices[0].message.content` ("AI returned an empty reply").

- [ ] **Step 0: `git init`, write `.gitignore`.**

- [ ] **Step 1: Write failing tests in `aiWriter/ai.test.ts`** using `node:test` + `node:assert/strict` and a fake `fetchFn`:
  - `shouldRewrite`: `"hi"` → true; `""`, `"   \n"`, `"/shrug"` → false.
  - `rewrite` sends correct request: assert URL, `method: "POST"`, `Authorization: "Bearer k"`, and parsed body deep-equals `{ model: "m", messages: [{ role: "system", content: "p" }, { role: "user", content: "hello" }] }`.
  - reply `"  Hi there!\n"` → resolves `"Hi there!"`.
  - empty `apiKey` → rejects `/No OpenRouter API key set/`, and `fetchFn` never called.
  - status 401 with body `{ error: { message: "bad key" } }` → rejects `/OpenRouter 401: bad key/`.
  - status 200 with body `{ error: { message: "x" } }` (no choices) → rejects `/empty reply/`.
  - status 200 with `choices[0].message.content: "   "` → rejects `/empty reply/`.

- [ ] **Step 2: Run** `node --test aiWriter/` — Expected: FAIL (module not found).

- [ ] **Step 3: Implement `aiWriter/ai.ts`** per the Interfaces block. `fetchFn` defaults to global `fetch`; read error body with `.json().catch(() => null)`.

- [ ] **Step 4: Run** `node --test aiWriter/` — Expected: all pass.

- [ ] **Step 5: Commit** `git add .gitignore aiWriter/ai.ts aiWriter/ai.test.ts docs && git commit -m "feat: add OpenRouter rewrite logic"`

### Task 3: Plugin wiring and settings window

**Files:**
- Create: `aiWriter/index.tsx`
- Create: `aiWriter/SettingsModal.tsx`

**Interfaces:**
- Consumes: `shouldRewrite`, `rewrite`, `RewriteConfig` from `./ai`.
- Produces (in `index.tsx`): `export const settings = definePluginSettings({ prompt, model, apiKey, rewriteEdits })` — `OptionType.STRING` for the first three (`model` default `"anthropic/claude-sonnet-5-5"`, `prompt` default `"Rewrite the user's message to be clear and well-written. Reply with only the rewritten message."`, `apiKey` default `""`), `OptionType.BOOLEAN` `rewriteEdits` default `false`.
- `SettingsModal.tsx`: `export function openSettingsModal(): void` — uses `openModal` from `@utils/modal`.

Vencord APIs to use (verified in current source):
- `definePlugin({ name: "AiWriter", description, authors: [{ name: "tymurd", id: 0n }], settings, chatBarButton: { icon, render }, onBeforeMessageSend, onBeforeMessageEdit })` from `@utils/types`.
- `ChatBarButton` (props `tooltip`, `onClick`, `onContextMenu`, children) and type `ChatBarButtonFactory` from `@api/ChatButtons`; render returns `null` unless `isMainChat`.
- `ModalRoot`, `ModalHeader`, `ModalContent`, `ModalFooter`, `ModalCloseButton`, `openModal` from `@utils/modal`; `TextArea`, `TextInput`, `Switch`, `Button`, `Forms`, `Toasts`, `showToast`, `React`/`useState` from `@webpack/common`.

- [ ] **Step 1: `index.tsx`**
  - Module-level `let aiEnabled = false;` plus a listener set so the button re-renders on toggle (`useState` + subscribe in the button component).
  - Button: sparkle SVG icon; highlighted (e.g. `color: var(--brand-500)`) when on. Tooltip `"AI mode: ON"` / `"AI mode: OFF"`. Left-click toggles, right-click (`onContextMenu`, `preventDefault`) calls `openSettingsModal()`.
  - Shared `async function maybeRewrite(msg: { content: string }): Promise<void | { cancel: true }>`: if `!aiEnabled || !shouldRewrite(msg.content)` return; show `"Rewriting…"` toast (`Toasts.Type.MESSAGE`); `try { msg.content = await rewrite(msg.content, { apiKey, model, prompt }) } catch (e) { showToast("AI Writer: " + e.message, Toasts.Type.FAILURE); return { cancel: true }; }`.
  - `onBeforeMessageSend(_, msg) => maybeRewrite(msg)`; `onBeforeMessageEdit(_, __, msg) => settings.store.rewriteEdits ? maybeRewrite(msg) : undefined`.

- [ ] **Step 2: `SettingsModal.tsx`** — modal with local state initialised from `settings.store`: Prompt (`TextArea`, ~6 rows), Model (`TextInput`), API key (`TextInput type="password"`), "Also rewrite edits" (`Switch`). Save writes all four into `settings.store` and closes; Cancel closes.

- [ ] **Step 3: Build** `cd Vencord && pnpm build` — Expected: success, no TS errors in `userplugins/aiWriter`. Also re-run `node --test aiWriter/` (still passes; `ai.test.ts` is not picked up by the Vencord build because only `index.tsx` is the entry).

- [ ] **Step 4: Commit** `git add aiWriter && git commit -m "feat: AiWriter chat-bar toggle, settings modal and send/edit hooks"`
